# PHP 8.5 Upgrade

- **Date:** 2026-10-23
- **Status:** Implemented
- **Scope:** `Dockerfile`, `composer.json`, `dbconfig.php`, `public/index.php`, `.github/workflows/php-lint.yml`, `README.md`

## Motivation

The runtime image was pinned to `php:8.4-fpm-alpine`. PHP 8.5 is the current stable
branch (8.5.12 released on 2026-10-22) and the application only uses APIs that are
unaffected by the 8.5 changes, so the upgrade is a base-image bump plus two small
hardening changes.

## What changed

| File | Change |
| --- | --- |
| `Dockerfile` | `FROM php:8.4-fpm-alpine` → `FROM php:8.5-fpm-alpine` (floating minor, currently 8.5.12 / Alpine 3.24). The `docker-php-ext-install mysqli`, Composer and nginx setup steps are unchanged. |
| `composer.json` | Added `"php": "^8.5"` to `require` so Composer refuses unsupported runtimes, plus a `lint` script (`find public dbconfig.php -name '*.php' -print0 \| xargs -0 -n1 php -l`). `aws/aws-sdk-php: ^3.0` is unchanged and resolves to 3.402.0. |
| `public/index.php` | Removed the two `curl_close($ch)` calls in the Keycloak token/userinfo flow. `curl_close()` is deprecated in PHP 8.5 and has been a no-op for `CurlHandle` objects since PHP 8.0, so behaviour is identical. |
| `dbconfig.php` | `new mysqli(...)` is wrapped in `try { … } catch (mysqli_sql_exception $e) { error_log(...); }` with `$link = null` as the default. Since PHP 8.1 mysqli throws on connection failure by default, which bypassed the existing `$link === null \|\| $link->connect_error` guards in `index.php` / `setup.php` and produced an uncaught exception instead of the friendly message. |
| `.github/workflows/php-lint.yml` | New workflow: runs `php -l` over `dbconfig.php` and `public/*.php` inside `php:8.5-cli` on push/PR (paths filtered to PHP files, `Dockerfile`, `composer.json`). |
| `README.md` | Requirements now list "PHP 8.5 (bundled in the Docker image)". |

## PHP 8.5 compatibility audit

Checked against <https://www.php.net/manual/en/migration85.deprecated.php> and
<https://www.php.net/manual/en/migration85.incompatible.php>.

| PHP 8.5 change | Found in codebase | Action |
| --- | --- | --- |
| `curl_close()` deprecated | `public/index.php` (2 calls) | Removed |
| `curl_share_close()`, `xml_parser_free()` deprecated | No | None |
| Non-canonical casts `(integer)`, `(boolean)`, `(double)`, `(binary)` deprecated | No (only `(int)`, `(string)`, `(bool)`) | None |
| `case …;` terminator deprecated | No | None |
| Backtick operator deprecated | No | None |
| `__debugInfo()` returning `null` deprecated | No | None |
| Constant redeclaration / closure rebinding deprecations | No | None |
| `$http_response_header` deprecated | No (uses cURL) | None |
| `chr()`/`ord()` range deprecations | No | None |
| Stricter `session_start()` options, `\|` in `$_SESSION` keys | No (no options array, no pipe keys) | None |
| `"array"`/`"callable"` `class_alias()` restriction | No | None |
| mysqli default exception mode (since 8.1) | `dbconfig.php` | Handled with `try/catch` |
| `utf8_encode()`, `strftime()`, `create_function()`, `money_format()` removals (older branches) | No | None |

## Known limitations

- No Keycloak instance was available in the verification environment, so the SSO
  authorization-code callback (`index.php?code=…`) and the logout redirect were not
  exercised end to end. The token/userinfo cURL code is unchanged apart from the
  removed `curl_close()` calls.
- AWS Route53 calls were not executed (dummy credentials); only client construction
  and page rendering were verified.

## Rollback

The code changes are compatible with PHP 8.4, so reverting only requires changing the
base image back to `php:8.4-fpm-alpine`. The `"php": "^8.5"` constraint in
`composer.json` must then be relaxed to `^8.4` as well.

## Not changed (tracked for later)

- `CMD php-fpm -D && nginx -g 'daemon off;'` still uses the shell form, which triggers
  the BuildKit `JSONArgsRecommended` warning. Switching to an exec-form CMD / entrypoint
  would let signals reach nginx directly, but it is unrelated to the PHP version bump.
- `build.yml` passes `VERSION` / `COMMIT` build args that the `Dockerfile` does not
  declare yet.
